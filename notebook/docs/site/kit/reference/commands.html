All exakit commands

Every command of the kit, 41 in all, with what it takes and what it does.

exakit help <command> prints a command's full reference on this computer, and exakit catalog <word> searches them.

Everyday

CommandTakesWhat it does
exakit status[--json]Is the database up and healthy?
exakit info[--json]Your connection details.
exakit start[<service>]Start the database and every add-on service, or one of them.
exakit stop[<service>]Stop the add-on services and the database, or one of them.
exakit sql'<statement>' | --file <path> | (stdin) [--json] [--write] [--help]Run one SQL statement, with the error translated.
exakit data-load[<file-or-folder-or-dataset>] [--force]Load a dataset (downloaded only when you pick it), one file, or a whole folder.
exakit logs[<target>] [-f] [--lines N] [--path] [--json]Every log the kit can show.
exakit autostartCome back automatically after a restart?

Personas and notebooks

CommandTakesWhat it does
exakit personalist | show <id> | plan [<id>] [--json] | add [<id>[,<id>]] | remove <id>Who the kit is set up for - Data Scientist or General: list, show, plan, add or remove one.
exakit notebook[jupyterlab | marimo] [check] [setup] [stop] [--no-browser] [--port <number>]Open JupyterLab or Marimo, connected to the local database (the notebook add-on).
exakit describe<SCHEMA.TABLE> [--sample <rows>] [--id <slug>] [--json] [--write <path>] | <id|SCHEMA.TABLE|draft.yaml> --approve [--role <slot>=<COLUMN>]... [--owner <who>] [--no-comments] [--json] | <id> --show [--version <n>] [--json] | <id> --versions [--json] | <id> --comments [--json] | --schema <SCHEMA> [--approve [--link <TABLE.COLUMN>=<TABLE.KEY>]... [--unlink <TABLE.COLUMN>]... [--owner <who>] [--no-comments]] [--json] | --model <NAME> --table <SCHEMA.TABLE>... [--link <SCHEMA.TABLE.COLUMN>=<SCHEMA.TABLE.KEY>]... [--ai] [--description <text>] [--dry-run] [--json] | --model <NAME> --refresh [--json] | --models [--json] | --model <NAME> --schemas <A,B,C> [--find-links] [--ai] [--dry-run] [--json] | --links <A,B[,C...]> [--ai] [--json]Draft each column's role in a table (key, time, measure, category, flag, text, identifier, other), approve it, and publish it as an Exasol Semantic Views model for the notebooks and AI clients.
exakit workflowlist | show <id> [--json | -j]The workflow logs the notebook helpers write: list them, show one.

Models and UDFs (udf-devkit, hidden for now)

CommandTakesWhat it does
exakit mlflowstart|stop|disable|status|url|replay [action options]Start or stop the local MLflow server, show its address, or replay pending runs.
exakit udf-setup[--language python|rust] [--force] [--yes] [--json]Python or Rust UDFs: install the official Python container (or the pinned Rust one) and prove it (the udf-devkit add-on).
exakit udf-usedefault [--language python|rust] [--yes] [--json] | <container.tar.gz> [--alias NAME] [--language python|rust] [--yes] [--json] | --listInstall a script language container: the kit's prebuilt one for this database, or a tarball of your own.
exakit udf-build<requirements.txt> [--alias <NAME>] [--yes]Build a container with your pinned packages and install it.
exakit udf-file<file> [<path in the bucket>]Copy a file into BucketFS and print the path a UDF reads it from.
exakit rust-udfnew <name> [--coefficients <file>] | build <name> | deploy <name> [--schema <SCHEMA>] [--yes] [--json]Create, build and deploy a Rust scoring UDF from exported coefficients.
exakit modelput|inspect|list|rm|prune|template [arguments]Model files in the bucket directory: put one (digest recorded, /buckets path printed), list them, find the scoring UDF template.
