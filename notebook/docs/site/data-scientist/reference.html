Command reference

All commands

Every public helper of exakit.nb, 111 in all, with the page that documents it.

Every notebook starts with import exakit.nb as nb. Each name below is one call a cell can make, and the same call a guided card makes behind its buttons.

CommandWhat it does
nb.addon_readyMake an add-on usable from here: install it when it is not (exakit marketplace <addon>), start it when it is a service and stopped (exakit start <addon>), and say its state and address.
nb.addonsThe marketplace's add-ons as exakit marketplace --list --json reports them: {id, name, about, status, installed, version, url}, and offered: False for one the kit's catalog does not offer yet (its marketplace/catalog.json says "visible": false, so no marketplace screen lists it).
nb.ai_clientsThe AI clients the kit can connect to the database (its MCP adapters), each {id, name, connected}, with connected from exakit mcp-status --json.
nb.approved_datasetsEvery dataset with an approved column map, newest approval first: {id, table, version, approved_at}.
nb.askDraft SQL from roles and the user's opted-in model endpoint; proposed_sql supports manual drafting.
nb.check_bucketThe deployment's bucket directory exists on this machine where the kit says it is, and - given a connection - a UDF sees it at its /buckets path too (skipped, with a note, when the container check fails).
nb.check_connectionThe database answers: its time, this session's id and its version, as one row (and one line).
nb.check_containerThe container behind alias runs a smoke UDF, and it has every package training needs.
nb.check_mlflowCheck the destination runs will really use: configured server, kit server, or local store.
nb.check_model_compatibilityRefuse a pickle whose scikit-learn version differs before any scoring SQL runs.
nb.chosen_datasetThe dataset a notebook works on: name when it is set; with None, the one approved last in a quickstart (so picking fraud_transactions there carries on here), else amazon_sales.
nb.clean_pathA path pasted into a cell, made usable: quotes and spaces around it, a file:// link, the shell's backslash escapes (My\ Data, from a drag into a terminal) and ~ are undone.
nb.column_map_versionsEvery saved version of a dataset's column map, oldest first: {version, approved_at, roles, slots, evidence} - what approving one of them again (RoleReview.approve) would restore.
nb.componentsThe kit's parts as exakit version --json reports them: {id, installed, available, status, add_on, ownership, remedy}, with a status of current, ahead, update_available, available (an add-on not installed) or missing; available is the version the kit would install or update to.
nb.confirm_sendBefore sampled rows go to a model endpoint: True at once for a table in the database; for a live source (the descriptor names a source) it names the source and asks, and only a yes sends.
nb.connectA pyexasol connection to the local database, opened from the kit's encrypted store, pinned to the database's TLS certificate once the kit has recorded it.
nb.connect_sourceConnect an external source as a virtual schema, from a notebook cell.
nb.connected_sourcesThe virtual schemas in the database (external sources) with their number of tables; empty when there is none.
nb.connector_inputsWhat exakit connect <connector> asks, from the kit's source engine (inputs: what its connect form reads, in the form's order).
nb.connectorsThe kinds of external source exakit connect takes, as its own menu lists them (the kit's source engine, catalog): {id, name, summary, aliases, tier, status, version, gate} - version the adapter the kit pins, gate why one is not available yet (empty when it is).
nb.continue_workflowThe workflow already going, without an id to paste: this kernel's, else the one inherited through EXAKIT_WORKFLOW_ID, else the last one started or resumed on this machine (a quickstart starts one); a new one named name only when there is none.
nb.count_nameThe count column, named after what is counted: ORDER_LINES, STORE_WEEKS; ROW_COUNT when the descriptor does not say (ROWS is an SQL word).
nb.current_versionThe approved version's number from current, or None when there is none (or the file does not hold one).
nb.current_workflowThe active workflow id: the session's, else the one inherited through EXAKIT_WORKFLOW_ID, else None.
nb.dash_toolsThe notebook's Dash Server tool adapter; each call is an MCP tool call.
nb.DashToolsSynchronous adapter for notebook cells, which already run an event loop.
nb.data_checksPrepare: one row per finding - CHECK, COLUMN_NAME, ROWS_AFFECTED, PCT, MEANS - for repeated keys, repeated identifiers, exact copies of a row, empty cells, placeholder values and a rare label.
nb.data_mapThe semantic map of the database: every table by origin (sample, local, source) with its rows, columns, column-map state and roles, then the links between tables - declared, found by an approved schema map, or a shared key-like column name across two tables (marked possible).
nb.DataMapWhat data_map found: tables, columns and links, each a list of dicts; DataFrames through the properties.
nb.DatasetA validated descriptor whose every role the database holds, with the SQL names the notebooks build queries from.
nb.datasetThe dataset name, checked against the database: a kit dataset id, a descriptor file or its folder, or a data file of your own (CSV, Parquet or JSON) with its descriptor beside it, which is loaded first (load_own_file).
nb.describeDescribe SCHEMA.TABLE (or a dataset id's table): the approved descriptor when the table still matches it, else a fresh draft.
nb.describe_schemaThe schema of dataset_or_schema (a dataset, or a schema name) as found now: its tables, rows and keys, and every many-to-one link between them with its evidence.
nb.descriptor_store_dirThe folder that holds the versions of the descriptor id (whether or not it exists yet); an id that is not a dataset id is refused, so no path is built from it.
nb.DescriptorNotApprovedA step that needs an approved descriptor was given a draft; the message says how to approve it.
nb.DocsWhat nb.docs() returns: the documentation at url.
nb.docsOpen the notebooks' documentation: all of it, one command's page, one page, or a search.
nb.DraftA descriptor proposed for a table (status draft), or the approved one describe() returned.
nb.draft_questionA Proposal for question drafted by rules from the column map (no AI model): read-only SQL, with the drafter's assumptions, not approved yet.
nb.exakitRun exakit <args> and show its output line by line as it comes (show=False keeps it quiet); the KitRun says how it ended.
nb.example_questionsUp to three questions this dataset's approved roles can answer, in its own column names.
nb.feature_ideasFeature ideas for this lab's data, each with the SQL that would make it: try one with try_feature.
nb.firstThe first dataset that was loaded, in the order given; says which one is used.
nb.forget_modelDelete what use_model(..., remember=True) saved (the model, Langfuse, or both) and clear it from this kernel.
nb.handoff_bundleWrite the bundle for ds and the workflow (the active one, else the last one on this machine, else none) into folder (default $EXAKIT_HOME/bundles/<workflow id>/; a bundle for no workflow is named after the dataset) and, with zip_it, a zip beside it.
nb.handoff_fromThe handoff record for ds as design 4 shapes it, built now and returned, nothing written: the descriptor's id, version, digest (digest_kind says whether it is the table digest or the file's) and source; the data digest (data_digest_kind); the feature view; the label and its positive class (label overrides it); the split (time over the date role by default; split="random" for a hash split, the only way to get one - without a date role and without that, a ValueError names the fix; split.explicit records the choice) and train_share; the training SQL; input and output schemas.
nb.handoff_is_staleNone when handoff still describes ds and its data; else the line 01_train prints before it refuses: the descriptor's version or digest changed (recomputed from ds: the same kind the handoff recorded), or - with a connection - the data digest no longer matches.
nb.HandoffBundleWhere the bundle is and what is in it.
nb.JoinedViewThe proposal for one wide view.
nb.kit_checkThe kit as it is now, in a few lines: installed or not, the database, each add-on service and its address, the datasets loaded.
nb.kit_statusexakit status --json as a dict.
nb.kit_updateexakit update from here (optionally one component: kit_update("notebook")).
nb.KitRunOne command run: the words it was called with, its exit code and everything it printed.
nb.LabOne model-lab run: the task, its settings, the data it read and what came out (board and pick for a prediction, groups or unusual rows otherwise).
nb.lab_dataThe approved data the lab trains on, read once (newest first, at most ROW_LIMIT rows): every usable column, with the ones that give the answer away (nb.leakage_check, unless leaks is given) and personal data left out (.left_out says why).
nb.last_workflowThe workflow started or resumed last on this machine, when its log is still there; else None.
nb.leakage_checkValidate: the columns whose values (almost) decide the label on their own - each a value or values where the label is (nearly) always 1 or always 0, covering most rows.
nb.list_schemasEvery schema with its number of tables, virtual ones (connected sources) marked.
nb.list_versionsThe version numbers stored for id (every v<n>.yaml), ascending; empty when none is stored.
nb.list_workflowsOne summary per log in the workflows folder, oldest first: id, name (from its start line), started, last (first and last timestamps) and events (the line count).
nb.load_own_fileLoad your own data and return it as a Dataset the notebooks run on (or a LoadedTable whose roles are reviewed next).
nb.load_sampleA dataset the kit offers (amazon_sales, fraud_transactions): used as it is when it is loaded, else loaded first with exakit data-load <id> (the cell waits for it), then checked against the database.
nb.load_sourceA table in a connected external source (a virtual schema).
nb.loaded_filesThe files exakit data-load put into the database, as the kit records them (its load receipts): one row per table, the latest load - {table, rows, file, loaded_at}.
nb.LoadedTableA file that has been loaded but has not yet received an approved descriptor.
nb.log_eventAppend one line to the active workflow's log; nothing when no workflow is active.
nb.log_sqlLog a statement sql() ran: the session and statement ids that find it in the database's audit log, the statement's SHA-256 (what traces and runs carry), how many rows came back, and the statement text - redacted, with a warning, when it looks credential-bearing (a PASSWORD or API_KEY column, say); this never raises, the query has already run.
nb.model_client(client, model ID) for EXAKIT_MODEL_ID and EXAKIT_PROVIDER_BASE_URL; EXAKIT_PROVIDER_API_KEY is optional for servers without authentication.
nb.model_labTrain task on the approved dataset: predict_yes_no (its target), predict_number (target_number), find_groups or find_unusual.
nb.model_listWhat exakit model list --json says: bucket_dir (the host folder), udf_root (the path UDFs read it under) and the models in it.
nb.model_settingsDisplay the chosen model and endpoint without the API key or custom header values; makes no request.
nb.model_setupSet up your model and Langfuse for this kernel, and say how to set them for every notebook.
nb.nameA result column named after a data column: CANCELLED + PCT -> CANCELLED_PCT; quotes, dots and spaces become underscores, so the name works unquoted in SQL.
nb.note_groupsPrint (and return) the note under a per-group result: one line per fact, in the data's own words.
nb.note_modelPrint (and return) the note under the small model's score, in words.
nb.note_trendPrint (and return) the note under a per-period result: the busiest period and the highest and lowest %.
nb.notebooksThe kit's notebooks in order ({id, persona, step, title, summary, file}), from its notebook catalog; only persona's when given.
nb.nounWhat a row is, from the descriptor's grain: "one row per order line" -> "order lines" (one=True: "order line"), "one row per store and week" -> "store weeks"; at most three words, up to a comma or a word such as "in" or "per"; "rows" when the descriptor does not say.
nb.persona_planWhat a persona (this kit's, when not named) brings that is still missing here: exakit persona plan --json - {persona, datasets{loaded, pending}, addons{installed, pending, unavailable}, nothing_pending}.
nb.personasThe kit's personas (personas/*.json): {id, title, summary, datasets, addons, visible}.
nb.prepare_trainingRefuse stale input, create the view, drop constant features and render the UDF and training SELECT.
nb.ProposalA question with the SQL proposed for it.
nb.read_connection_stringRead a source's connection string exactly as exakit connect --url does: it is handed to the kit's engine (its paste command, on standard input, never as an argument).
nb.read_handoffThe handoff as a dict: from a path to the file, from <id>-v<n> (that version's file), or from a descriptor id (the file with the highest version in the handoffs folder).
nb.review_rolesProfile the loaded sample, file or connected table, show evidence and role choices, then await approval.
nb.RoleReviewOne proposal.
nb.sample_datasetsEvery sample dataset this kit ships, in the kit's order: {id, label, description, schema, default, loaded, described} - described: it ships a column map, so nb.load_sample opens it ready to use.
nb.save_descriptorWrite a descriptor document as YAML, in the layout of the kit's own descriptor.yaml files - always as schema_version 2: a schema_version 1 document (or one without the record keys) is written as version 1 with status (draft unless the document, or status, says approved), the owner (EXAKIT_DESCRIPTOR_OWNER, else the OS user), created now, drafted by the user and, when given, source (file:<path> for a file's descriptor).
nb.SchemaMapThe schema as found (a draft) or as approved: doc holds its tables and links.
nb.shareMake a draft from approved data and inspected SQL; measure=count enables count totals and composition.
nb.ShareDraftA dashboard prepared from an approved dataset and one query.
nb.show_rolesThe descriptor's roles, one per line, as the notebook will use them.
nb.show_sqlPrint the last statement sql() ran, so a result can always be traced to the query behind it.
nb.source_engineAsk the kit's own source engine (setup/virtual-schemas/engine/cli.py, the coordinator behind exakit connect and exakit source) one of the questions its connect form asks, and return its --json answer:
nb.SourceProblemA source cell that cannot go on, said in one short message: no traceback in a notebook.
nb.SourceTestWhat test_source found, one check per line: (what was checked, passed, what it said).
nb.sqlRun a query and return its rows as a pandas DataFrame; the statement is remembered for show_sql().
nb.test_sourceTest a source before connecting it, changing nothing: first the kit's own check of every input (`exakit connect ...
nb.themesSort each side's texts into themes with endpoint = (client, model) from nb.model_client(); return the table (a pandas DataFrame when pandas is there, else a list of rows) and print the note.
nb.traceGroup the model calls made inside the block into one trace in the user's own Langfuse project, tagged with the database session, the sample SQL, the workflow id and, given a dataset, its id, descriptor digest and descriptor version (trace_tags).
nb.tracingWhether LANGFUSE_PUBLIC_KEY, LANGFUSE_SECRET_KEY and LANGFUSE_BASE_URL (or LANGFUSE_HOST) are all set, so trace() records to the user's Langfuse.
nb.TrainingPlanWhat in-database training will run, prepared from an approved, fresh handoff: the feature view and its columns, the script that creates the training UDF, the training SQL and its parameters.
nb.try_featureRetrain the lab's picked model with idea added, on the same split: {verdict, text, series}.
nb.typed_viewThe proposal for ds's table: its types, its cleaning and the CREATE VIEW, built from the data and the descriptor.
nb.TypedViewThe proposal.
nb.use_mlflowThe MLflow server this kernel records runs to: tracking_uri (empty: the kit's own MLflow, or what the shell set); login=True asks for the server's username and password (hidden).
nb.use_modelYour model and Langfuse tracing for this kernel.
nb.use_tableA table already in the database, to describe next (review_roles): SCHEMA.TABLE.
nb.workflowStart a workflow (a new id, a start line in its log) or, with resume, continue an existing one.
nb.workflow_logEvery line of a workflow's log, in order.
nb.write_handoffBuild the handoff (handoff_from) and write it to $EXAKIT_HOME/handoffs/<id>-v<n>.json - the folder 0700, the file 0600, replaced whole (a temporary file renamed over it) so a reader never sees half of one.
