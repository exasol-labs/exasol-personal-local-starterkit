Command reference

In-database training

Prepare the ML Engineer's in-database training from an approved, fresh handoff (ML-3, design 7).

Determinism (AC-ML3.4): the plan is a pure function of the handoff and the options - the features keep the handoff's order (the input schema, which the feature view fixes), a constant feature is dropped by a MIN/MAX query whose answer depends on the data alone, and the rendered UDF trains LogisticRegression(random_state=seed, solver="lbfgs") over rows it sorts first - so the same handoff, seed and data give the same metrics and the same coefficients.

nb.prepare_training

Refuse stale input, create the view, drop constant features and render the UDF and training SELECT.

The caller creates create_script then passes training_sql to exasol_mlflow.start_run(). container is the alias of the Python container the UDF runs on (the notebook's CONTAINER); None resolves it with udf_container() - PYTHON3_ML before PYTHON3 from the kit's manifest, EXAKIT_UDF_CONTAINER first - and raises with the fix when none is installed, before anything is written. model_dir is accepted for the earlier signature; the model comes back through the query, in parts of up to 1 MB when it is bigger - no bucket is written. class_weight is None or "balanced", passed to logistic regression and recorded in the plan; it never changes the holdout split.

Used in: ml-engineer/01_train

Training handoff

The handoff from the Data Scientist to the ML Engineer (DS-3 -> ML-3, design 4): one JSON file that holds everything 01_train needs to train without opening the descriptor - which descriptor version and digest it came from, a digest of the data, the feature view built from the roles (as CREATE OR REPLACE VIEW SQL), the label and its positive class, the training SELECT with a reproducible time split, and the input and output schemas.

ML Engineer checks

The three things the ML Engineer's notebooks depend on, one check each (ml-engineer/00_quickstart): the database's Python container answers a smoke UDF with the packages training needs, the MLflow server is reachable, and the bucket directory is where the kit expects it.
