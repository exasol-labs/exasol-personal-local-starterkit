`01_explore` reads the dataset you approved. Its first cell holds the choices:

```python
DATASET = None          # None: the dataset approved last in the quickstart
USE_AI_THEMES = False   # True: your model sorts the texts into themes
USE_JOINED = False      # True: create and use the joined view
USE_PREPARED = False    # True: create and use the typed, cleaned view
```

## Prepare

```python
workflow_id = nb.continue_workflow("explore")
connection = nb.connect()
dataset = nb.review_roles(connection, nb.chosen_dataset(DATASET)).dataset(draft_ok=True)

findings = nb.data_checks(connection, dataset)
schema_map = nb.describe_schema(connection, dataset)
typed_view_proposal = nb.typed_view(connection, dataset)
```

Read the findings and the two proposals. Nothing is created until you set `USE_JOINED` or `USE_PREPARED`. See [Prepared views](/data-scientist/concepts/prepared-views).

## Explore

Each query shows its SQL before its result, and a plain-language note under it.

```python
rows = nb.sql(connection, f"""
SELECT {dataset.col("category")} AS GROUP_, COUNT(*) AS N
FROM {dataset.fact_table}
GROUP BY 1 ORDER BY N DESC""")
nb.show_sql()
```

`nb.note_groups` and `nb.note_trend` write the notes under the group and over-time results.

## Model and validate

```python
leaking = nb.leakage_check(connection, dataset)
```

The notebook then reads up to 20,000 rows, trains a small baseline model on the category, the entity and the month, scores it on rows it has not seen, and shows what it leans on. `nb.note_model` says in plain words what the score means.

For more control, the **model lab** lets you choose the task, the model and the split:

```python
lab = nb.model_lab(connection, dataset)        # task, model and split are arguments
ideas = nb.feature_ideas(lab)                  # ideas, each with the SQL that would make it
result = nb.try_feature(lab, ideas[0])         # retrain with one idea added, on the same split
```

See [Model lab](/data-scientist/reference/lab).
