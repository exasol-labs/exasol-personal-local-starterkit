Monitoring means noticing that something has changed since you last looked, and deciding what to redo. A table gets a new column. A column map is approved again. A model is retrained on newer rows. In most data science work this loop never ends. The kit helps with the record and with the checks it can make when you run a step again. It does not watch your data in the background, it does not detect drift, and it does not retrain anything on its own. You do the iterating, and the kit tells you where to go back to.

## Where you do it

## How we used it

Suppose someone adds a column to `AMAZON.ORDER_LINES`. The kit does not notice until you describe the table again. Here is how you find out and what you do, in four steps:

```python
workflow_id = nb.continue_workflow("explore")   # this kernel's workflow, or the last one on this computer
events = nb.workflow_log(workflow_id)           # every line, in order
draft = nb.describe("AMAZON.ORDER_LINES")       # a draft if the table changed since its approval
versions = nb.column_map_versions("amazon_sales")
```

The workflow log shows what the last run did. The describe call returns a draft when the schema changed, and the changed columns say so. You review the draft, correct what is wrong, and approve. The approval writes the next version and rebuilds every semantic model the table is in. Then run the notebooks again, from the first cell. They read the newest approval.

## What you have at the end

A record of what each run did, a column map whose versions you can read and restore, a semantic model that matches the approved roles, and a plain list of what needs redoing. The loop has no end. When something changes, go back to the stage in the table on [What changed, and where you go](/data-scientist/monitor/what-changed) and work forward from there.
