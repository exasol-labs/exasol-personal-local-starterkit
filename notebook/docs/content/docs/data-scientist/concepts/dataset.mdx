A **dataset** is a table in the database together with its approved [column map](/data-scientist/concepts/descriptor). The notebooks never read a table directly. They read a dataset, and build every query from its roles.

## Where a dataset comes from

| Source | How it gets in |
|---|---|
| A kit dataset | `nb.load_sample(connection, "amazon_sales")` |
| Your own file or folder | `nb.load_own_file("~/sales-data/orders.csv", "SALES", conn=connection)` |
| A table already in the database | `nb.use_table(connection, "MY_DATA.ORDERS")` |
| An external source | `nb.connect_source(...)`, then `nb.load_source(connection, "VS_SALES.ORDERS")` |

See [Load data](/data-scientist/guides/load-data) for each one in full.

## Picking the dataset in a notebook

One assignment picks the data: `SAMPLE = "..."` in the quickstart and `DATASET = "..."` in the other notebooks.

```python
dataset_id = nb.chosen_dataset(DATASET)        # DATASET = None: the dataset approved last
dataset = nb.dataset(connection, dataset_id)   # refuses a column map that is not approved
```

With `DATASET = None`, each notebook follows the dataset you approved last in the quickstart. Approve a different one there and the other notebooks pick it up when you run their first cell again.

## Reading roles, not column names

```python
dataset.fact_table            # the table or view the steps query
dataset.has("label")          # is there a target?
dataset.col("label")          # its column, quoted for SQL
dataset.group_by()            # the category, else the entity, else the target
dataset.missing               # the roles no column plays, each with the reason
```

Because the queries come from roles, the same cell runs on `amazon_sales`, on `fraud_transactions` and on your own table.

<Callout>

A role no column fits is never guessed. `dataset.has(...)` is false, the step that needs it skips, and it says why.

</Callout>
