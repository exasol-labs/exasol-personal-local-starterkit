## Personas and installation

- Rename AI Scientist to Data Scientist and complete the role-specific add-on bundles. Both personas select Pharma and Banking data, detected AI clients, Notebook and JSON Tables. Data Scientist also selects Dash Server; ML Engineer adds UDF devkit and the local MLflow service. Combining personas selects their union once.
- Keep shell and PowerShell behavior aligned, report partial failures with retry commands, and apply notebook package pins to the notebook and UDF environments where appropriate.
- Display the current installation activity immediately above the active progress bar inside the add-on table.

## Descriptors, workflow logs and handoff

- Add descriptor schema version 2 with explicit versions, approval state, owner, source, digest, evidence and missing roles; retain compatibility with version 1 descriptors.
- Add table profiling, descriptor drafts, role review and approval, descriptor-store resolution and metadata write-back for the local data flow.
- Add shared workflow IDs and logs across notebook steps, saved SQL, tracing and the Data Scientist to ML Engineer handoff. Redact credential-like SQL from workflow records and include training SQL in the shared workflow.

## Jupyter, Marimo and bundled notebooks

- Add the complete **50-notebook official Notebook Connector collection** for Jupyter and equivalent Marimo lessons, with a library index and 22 supporting assets. The reviewed upstream snapshot is pinned to `14e2c7ad088b7109aa21d283e98f3126bbbe27e5`.

- Add SQL/dataframe, decision-tree, UDF package-check and decision-tree UDF examples. Add scientific Python dependencies to the notebook environment and the prebuilt ML container's declared packages.
- Fix stale build output causing notebook helper packaging to omit the newer `exasol_mlflow.start_run(..., handoff=...)` API. Report notebook refresh failures on both platforms.
- Document how Notebook Connector, private notebook dependencies and bundled files are installed and updated. Preserve user notebook edits and the collection's copy receipts.
- Cloud and virtual-schema examples remain reference-only; they do not configure or run those integrations.

## ML training, MLflow, models and Rust

- Add managed MLflow server commands and service lifecycle integration, including enabled-state handling and PowerShell server-process recognition.

## Ownership, update and uninstall

- Record `kit`, `user` or `unknown` ownership independently for the launcher, database, exapump, Python driver and add-ons. Component listings expose an Owner column plus `ownership` and `installed_by_kit` in JSON.
- Reuse compatible user-installed components without reinstalling them. Preserve user-owned and untracked shared components during updates and uninstall. Report broken or incompatible user-owned tools instead of replacing them automatically.
- Record binary paths and checksums so a user replacement at the same path is preserved. Publish kit ownership only after the receipt is complete, and use recorded binary paths during removal rather than deleting an unrelated same-named program.
- Store kit exapump profiles privately beneath the kit home and retain shared user profiles. Preserve explicitly recorded user component paths beneath the kit home during full uninstall, including broken add-ons whose version probes fail.
- Update the bundled lifecycle, Python and exapump guidance and the Mac manual runbook for ownership-aware removal and local-checkout installation.
