One table you have never seen: how the Data Scientist persona is built

A data scientist installs the kit, loads a dataset or their own file, gets an approved description of it, checks it is clean, explores it with every SQL statement visible, tests one idea with a small model, and shares a result whose numbers they checked. This page describes what the kit does at each step, as the code on this branch does it.

MCP server: the one beside the database, read-only, self-healing

Everything the user does happens in a notebook that opens already connected, with no password in it. The column map (the descriptor) is proposed by the kit from a profile of the data and approved by the user; every later step reads it, which is why changing one assignment, DATASET = ..., moves every notebook to another dataset. The ML Engineer persona is switched off on this branch (kept, not removed) so the work can focus here.

Three reference datasets, each in its own schema. They are downloaded from the kit's datasets release when picked (the General persona's TPC-H, energy and weather ship inside the kit and load offline).

fraud_transactionsFRAUD.TRANSACTIONS51,000FRAUDULENT (4.9%)messy on purpose: 1,000 repeated ids, ~5% gaps in five columns, two placeholders, no date

How a dataset reaches the database

  1. exakit data-load fraud_transactions (or the quickstart's load cell) downloads fraud_transactions-2026-11-06.tar.gz and checks its SHA-256 against manifest.json.
  2. Every CSV in it is checked against its own digest, then loaded with exapump into the dataset's schema by its 01_create_schema.sql.
  3. 03_verify_setup.sql must answer OK on every row (row count, label count, the kept duplicates); a FAIL blocks marking it loaded.

Your own CSV, Parquet or JSON file goes in from the quickstart (SOURCE) or nb.load_own_file(), and then through the same describe and approve step as a sample.

Licences. All three come from Kaggle; their licences are recorded as not confirmed (terms.confirmed: false). Check the pages before redistributing.

04The column map (descriptor)

The kit profiles the table (type, share of empty cells, distinct values, date span, text length), proposes a role for every column with the evidence that chose it, and the user corrects and approves it in a picker - no YAML to edit.

Column roles

key, time, measure, category, flag, text, identifier, other - one per column.

Slots the notebooks read

key, time (date), target (label), category, entity, text. An empty slot carries its reason, and the steps that need it skip and print that reason.

Draft, approve, version

  • A draft is enough to explore. Ask your data and Share call require_approved and refuse a draft, saying how to approve it.
  • Approving writes v<n>.yaml and current.yaml under ~/.exasol-starter-kit/descriptors/<SCHEMA.TABLE>/; a version file is never rewritten.
  • The roles are published as a view, EXAKIT_SEMANTIC.<SCHEMA>__<TABLE>, whose column comments carry them; agents read the roles from there over MCP.
  • Approving roles that the current version already has writes nothing and says where that version is stored (and the view, when it exists).
# fraud_transactions, shipped descriptor (excerpt)
grain: "one row per transaction (1,000 transactions appear twice)"
slots: { key: ROW_ID, time: null, text: null, target: FRAUDULENT, category: TRANSACTION_TYPE, entity: LOCATION }
columns:
  "TRANSACTION_ID": {role: "identifier", evidence: "98% distinct"}
  "DEVICE_USED":    {role: "category",   evidence: "4 distinct"}
  "FRAUDULENT":     {role: "flag",       evidence: "0 95.1%, 1 4.9%"}

06How every cell follows the data

No notebook names a column or a table. Four rules hold that:

  1. One assignment picks the data. DATASET = None means "the dataset approved last in a quickstart" (nb.chosen_dataset), else amazon_sales; any id or a file path with its descriptor beside it also works.
  2. Columns come from roles. ds.col("category"), ds.col("label"), ... and ds.fact_table; a role the data does not have is None, never guessed.
  3. Result columns are named after the data. nb.name() and nb.count_name() turn CANCELLED into CANCELLED_PCT and the grain into ORDER_LINES or TRANSACTIONS; Share's query, title and app name follow the same rule.
  4. A missing role skips, with its reason. No date (fraud_transactions): no trend, and the model leaves the month out. No text (all three): the text step skips.

Two tests hold this: SwapTest renders every SQL f-string for two datasets and requires them to differ only in descriptor values, and MissingRolesTest removes each role in turn and requires every step that needs it to skip, not fail.

07Prepare: is the data clean?

nb.data_checks(conn, ds) runs a handful of SQL statements built from the descriptor (shown and logged like every other query) and prints one sentence per finding saying what it does to a result. It changes nothing.

CheckHow it is foundOn fraud_transactions
repeated ida key or identifier that is almost one per row but repeats; the message quotes the descriptor's grainTRANSACTION_ID: 1,000 rows
exact copiesrows equal in every column but the key881 rows
empty cellsCOUNT(*) - COUNT(column) for every columnfive columns, ~2,500 each

On walmart_sales the same cell reports that the table passed every check; on amazon_sales it finds 8,597 repeated ORDER_IDs (expected: one row per order line), 6 exact copies and the empty courier and amount columns.

08Validate: leakage and baselines

nb.leakage_check(conn, ds) looks at every column with at most 50 values (not the key, identifiers or text) and flags one whose values almost decide the label on their own: values where the label is at least 99% one way cover at least 95% of rows and catch at least 90% of the label-1 rows. Such a column was usually written after the outcome. The model leaves it out.

- STATUS gives CANCELLED away: CANCELLED is 1 whenever STATUS is 'Cancelled'.
  It was probably written after the outcome - leave it out of any model.

The model's score is ROC AUC on a quarter it has not seen, with a note in plain words ("about as good as guessing" near 0.5). A rare label is called out in Prepare, so accuracy is never the measure.

09The small model

A one-hot logistic regression with balanced class weights and a stratified, seeded split (random_state=0), on this computer. Its features are what the map names and the leakage check allows:

  • the category and the entity, as text;
  • the month of the date, only when there is a date.

With a date it reads the newest 20,000 rows; without one, the first 20,000 by the key - the same rows on every rerun either way. It needs a label and a category or entity. The Model clues cell lists the values the model leans on each way, at most half of them per side, so no value appears on both.

10Ask your data

  1. A question in plain English. With DRAFT_WITH_MODEL = True the user's own model drafts SQL from the approved map (every column with its role, evidence and note; no rows are sent); otherwise a starter query built from the roles.
  2. The proposal shows the SQL one clause per line, what the model assumed and what to check. Nothing has run.
  3. proposal.approve() fixes the exact text (its digest is logged); proposal.run() refuses anything else.
  4. It runs through the MCP server beside the database, as the read-only user: one SELECT or WITH, at most 1,000 rows. A draft map is refused.

11Share a checked result

The share notebook counts rows by the category (else the entity, else the label), named after the data, and builds a Dash Server dashboard from that one visible query:

  1. nb.share(ds, QUERY, TITLE, APP_NAME) prepares a draft carrying the query digest and the descriptor version.
  2. draft.preview(...) publishes a preview the user opens and compares with the SQL.
  3. draft.confirm(..., figures_checked=True) publishes it only after the user says the figures are checked.

Needs exakit marketplace dash-server and exakit start dash-server (port 5100 by default).

12Lineage: the workflow log

Every notebook starts or resumes a workflow (wf-YYYYMMDD-xxxxxx). Each SQL statement (with its digest and row count), each descriptor draft and approval, each approved question and each trace is one line in ~/.exasol-starter-kit/workflows/<id>.jsonl, in order. Paste the quickstart's id into WORKFLOW_ID in the other notebooks to keep one log.

13AI agents through MCP

Every AI client the kit connects (Claude, Claude Code, Codex, Cursor, VS Code Copilot, Gemini CLI, OpenCode, Continue) reaches the database through one MCP server: the official Exasol MCP server that the Exasol Personal launcher runs beside the database, at http://127.0.0.1:4896/mcp, connected as the dedicated read-only user. Client configs hold the URL and no password; Claude Desktop goes through uvx mcp-proxy.

There is no fallback server. When it does not serve, exakit mcp-setup and exakit mcp-doctor heal it:

CaseWhat the kit does
read-only user missingsets it up again
port 4896 taken by another programmoves the server to the first free port of the next 20 and records it
deployment from an older launcher asks for a restartrestarts the database once (data kept)
container did not startrecreates it once
launcher before 2.4.0says so, with the fix exakit update personal
still not servingquotes the launcher's own reason, keeps the clients on the URL, marks it not validated for the doctor

14Your model and Langfuse

Explore and Ask open with an optional cell: fill in MODEL_ID, PROVIDER_BASE_URL (any Chat Completions endpoint, a local one too) and LANGFUSE_BASE_URL, run it, and the keys are asked for in a hidden prompt. They stay in the notebook's kernel only - never in the file, its outputs or on disk. Left empty, the cell changes nothing; exporting the same variables before exakit notebook still works. A key is never sent over plain http:// to another machine.

15Credentials and safety

  • No host, user or password in any notebook, helper or output template; a test greps every shipped file for them.
  • Notebooks connect from the kit's store; passwords live in files under ~/.exasol-starter-kit/credentials/.
  • The database certificate is pinned (trust on first use) for every kit-built client.
  • AI clients reach the database only as the read-only user; writes are rejected by the database itself.
  • No SQL from Ask runs before the user approves that exact text.

18Known limits

  • Licences of the three datasets are not confirmed.
  • No dataset has a text column, so the text step (and its Langfuse trace) is exercised only on the user's own data.
  • Share needs Dash Server running; it was not part of the live run above.
  • The hidden prompt of the settings cell is shown by Jupyter; in Marimo it may not appear, and the cell then says how to set the key in the terminal.
  • The ML Engineer persona is switched off on this branch; its notebooks and training code stay.

19Troubleshooting

A step says "Skipped - … needs the date role".
The data has no column for that role (no date in fraud_transactions). It is a fact about the data, not an error.
"training needs an approved descriptor: … is a draft".
Approve it in the quickstart's review cell, or exakit describe <id> --approve.
Ask fails with "The Exasol MCP server … did not answer".
Run exakit mcp-doctor: it heals the server beside the database and says what it could not fix.
The dataset download fails offline.
Point EXAKIT_DATASETS_MIRROR at a folder (or an https URL) holding the archive.

21Glossary

Descriptor (column map)
The approved description of one table: every column's role with its evidence, and the slots the notebooks read.
Slot
One of key, time, target, category, entity, text: the column a notebook step reads for that purpose.
Leakage
A column that knows the outcome because it was written after it; it makes a model look perfect and fail on new rows.
Baseline
The simplest answer a model has to beat, such as always predicting the common class.
ROC AUC
How often the model ranks a label-1 row above a label-0 row: 0.5 is guessing, 1.0 is perfect.
Sidecar
A container the Exasol Personal launcher runs beside the database; the MCP server is one.
Workflow
One id that links the queries, descriptor versions, approvals and traces of one piece of work.
