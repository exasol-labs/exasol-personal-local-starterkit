# Amazon S3 · Federation guide

> **Federation** lets your local Exasol query JSON, JSON Lines, CSV and Parquet
> files in an Amazon S3 bucket in place, without copying them.
> `exakit connect s3` makes them a virtual schema, `VS_<NAME>`, that you query
> with SQL. An EDML mapping file says which files become which table; leave it
> empty and the kit drafts one from the bucket.

> **Easiest: let your AI agent do it.** The kit installs the skill
> `exasol-vs-s3` for your AI client; it knows this connector. A ready-to-use prompt is in
> [Ask your AI agent](#ask-your-ai-agent).
>
> **You still need, on your computer:** the AWS CLI (`aws configure`) or the
> AWS Console, as someone who may create an IAM user and its access key.

## At a glance

| You need | Where to find it |
|---|---|
| The bucket and its region | S3 → Buckets → the AWS Region column ([step 1](#1-bucket-and-region)) |
| A mapping (optional) | One `.json` file per table, or let the kit draft it ([step 2](#2-the-mapping)) |
| A read-only access key | IAM → Users → a new user with a read policy ([step 3](#3-a-read-only-access-key)) |
| Network access | Only if a bucket policy limits source IPs ([step 4](#4-network)) |

## Ask your AI agent

Copy this prompt, fill in the `<...>` parts, and give it to your agent:

```text
Connect the files under s3://<bucket>/<folder>/ to my local Exasol with exakit.
Use the exasol-vs-s3 skill. The bucket is in <region>. Create a read-only IAM
user and access key for it, draft the mapping from the files, and write the
secret key to a file, never into the chat.
```

Prefer to do it by hand? Follow the steps below.

## What `exakit connect` asks for

### Required

| Field | Example | Where it comes from |
|---|---|---|
| Name (alias) for this connection | `docs` | You choose it. `docs` gives the schema `VS_DOCS`. |
| S3 bucket name | `my-bucket` | S3 → Buckets ([step 1](#1-bucket-and-region)). |
| AWS region of the bucket | `eu-central-1` | S3 → Buckets → the AWS Region column ([step 1](#1-bucket-and-region)). |
| Secret access key | (hidden, or a file) | The access key you make ([step 3](#3-a-read-only-access-key)). |
| Access key ID | `AKIA...` | The access key you make ([step 3](#3-a-read-only-access-key)). The form always asks for it; a script may leave it out when the secret it gives is the credential file (the JSON `aws iam create-access-key` prints). |

### Optional

| Field | Default if left out | Example |
|---|---|---|
| EDML mapping (a .json file or a folder of them) | the kit drafts one from the bucket ([step 2](#2-the-mapping)) | `./mapping` |

## Connection string you can paste

```text
s3://my-bucket/orders/
https://my-bucket.s3.eu-central-1.amazonaws.com/orders/
https://s3.eu-central-1.amazonaws.com/my-bucket/orders/
```

| String | Fills |
|---|---|
| `s3://bucket/...` | bucket |
| `https://bucket.s3.<region>.amazonaws.com/...` | bucket and region |
| `https://s3.<region>.amazonaws.com/bucket/...` | bucket and region |

- The path after the bucket is not used: the mapping names the files.
- A query string (a presigned URL) is a credential and is never used as the
  key. Give the access key when asked.
- The string never holds the access key, and it is optional: press Enter alone
  at the prompt and `exakit connect` asks for the fields one by one.

**Where to copy it from.** You do not build the string:

- S3 → Buckets → `<bucket>` → select the folder → **Copy S3 URI**. That gives
  `s3://<bucket>/<folder>/` and fills the bucket.
- An object's page (Object overview) shows its **Object URL**
  (`https://<bucket>.s3.<region>.amazonaws.com/...`). That fills the bucket and
  the region.

## Where to find each value

### 1. Bucket and region

- **Console:** S3 → Buckets → the AWS Region column.
- **CLI:**
  ```bash
  aws s3api get-bucket-location --bucket my-bucket   # null means us-east-1, EU means eu-west-1
  aws s3 ls s3://my-bucket/orders/ --recursive | head
  ```

A bucket name with dots is refused: its HTTPS name does not match the S3
certificate.

### 2. The mapping

One `.json` file per table, or a folder of them (at most 50). `source` is the
key or glob inside the bucket:

```json
{"$schema": "https://schemas.exasol.com/edml-2.1.0.json",
 "source": "orders/*.jsonl", "destinationTable": "ORDERS",
 "mapping": {"fields": {"order_id": {"toDecimalMapping": {"decimalPrecision": 10, "decimalScale": 0}},
                        "status": {"toVarcharMapping": {"varcharColumnSize": 20}}}}}
```

CSV and Parquet may leave out `mapping`; their columns are inferred. JSON needs
its fields.

**Or let the kit draft it.** Leave the mapping empty, or give
`--set mapping=auto`. After you give the access key, the kit:

- lists the bucket and makes one table per folder and file type
  (`data/orders/*.jsonl` becomes `ORDERS`);
- for JSON, reads the first 64 KiB of a sample and types the top-level keys:
  whole numbers `DECIMAL(36,0)`, decimals `DOUBLE`, `true`/`false` `BOOLEAN`,
  ISO dates `DATE`, ISO timestamps `TIMESTAMP`, nested values as JSON text, the
  rest `VARCHAR(2000)`. A value that does not convert reads as NULL;
- leaves CSV and Parquet to the adapter to infer;
- drafts at most 25 tables from at most 10,000 objects, and names what it
  skipped (`_SUCCESS`, dot-files, `.ndjson`, a `.json` file holding an array).

The draft goes to `~/.exasol-starter-kit/sources/<name>/edml/`. At the terminal
you see the tables: press Enter to use them, `e` to open the folder and edit
them first, or `n` to give a mapping instead.

A key limited to one prefix (as in step 3) cannot list the whole bucket. Give
that folder: `--set mapping=auto:orders/`.

### 3. A read-only access key

The key needs `s3:ListBucket` on the prefix and `s3:GetObject` on its objects,
plus `kms:Decrypt` for a KMS-encrypted bucket.

- **Console:** IAM → Users → Create user (`exakit-docs-reader`, no console
  access) → Attach policies directly → Create policy → JSON (below). Then the
  user → Security credentials → Create access key → Third-party service →
  download the `.csv`.
- **CLI:**
  ```bash
  cat > exakit-s3-read.json <<'JSON'
  {"Version": "2012-10-17", "Statement": [
    {"Effect": "Allow", "Action": "s3:ListBucket", "Resource": "arn:aws:s3:::my-bucket",
     "Condition": {"StringLike": {"s3:prefix": ["orders/*"]}}},
    {"Effect": "Allow", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::my-bucket/orders/*"}]}
  JSON
  aws iam create-user --user-name exakit-docs-reader
  aws iam put-user-policy --user-name exakit-docs-reader --policy-name exakit-read \
    --policy-document file://exakit-s3-read.json
  umask 077; mkdir -p ~/.config/exakit
  aws iam create-access-key --user-name exakit-docs-reader > ~/.config/exakit/docs-key.json
  ```

- The CLI's JSON holds both the key ID and the secret.
- From the console `.csv`, put only the secret in a file, and give the key ID
  with `--set access_key_id=`.
- `aws sts` temporary credentials work too: give the whole JSON, session token
  included. They expire.
- The kit never reads `~/.aws`.

### 4. Network

Nothing to open by default.

- A bucket policy that limits `aws:SourceIp` must include your public IP
  (`curl https://checkip.amazonaws.com`).
- A bucket reachable only through a VPC endpoint cannot be read from your
  computer.

## Connect

```bash
exakit connect s3
```

1. Pick **Amazon S3** in the Federation picker.
2. Paste a connection string (hidden), or press Enter on an empty line to type
   the fields instead. Then answer each field above.
3. The kit checks the mapping (or drafts it after the access key), shows a plan
   with the mapped tables, and connects.
4. The first connect also runs **Enabling Federation**: it installs Java in the
   database (one restart).

Your tables appear as `VS_DOCS.ORDERS`.

**Without prompts** (scripts and AI agents):

```bash
exakit connect s3 --name docs --set bucket=my-bucket --set region=eu-central-1 \
  --set mapping=./mapping --password-file ~/.config/exakit/docs-key.json --yes
```

- Add `--dry-run` to see the plan first.
- Leave out `--set mapping=...` and the mapping is drafted from the bucket; the
  connect prints its tables. For a key limited to one prefix, give
  `--set mapping=auto:orders/`.

**Windows:** paste the URL at the prompt rather than `--url`. For a quoted name
in `exakit sql`, pipe the statement in, or use `exakit sql --file query.sql`.

## Query

```bash
exakit sql "SELECT * FROM VS_DOCS.ORDERS LIMIT 10"
```

```powershell
# Windows PowerShell: pipe a statement that has quoted names
'SELECT "x" FROM VS_DOCS.T' | exakit sql
```

## Troubleshooting

| Error you see | Why | Fix |
|---|---|---|
| "AccessDenied ... not authorized to perform: s3:ListBucket" | The key lacks the action on that prefix, or a bucket policy on `aws:SourceIp` refuses your IP (it answers the same). | Grant the action on that prefix ([step 3](#3-a-read-only-access-key)), or allow your IP. Then `exakit source check docs`. |
| "PermanentRedirect", "must be addressed using the specified endpoint" | Wrong region. | `exakit source remove docs`, then connect with the bucket's region. |
| "RequestTimeTooSkewed" | The database clock is off by more than 15 minutes. | `exakit stop`, then `exakit start`. |
| "InvalidAccessKeyId", "signature we calculated does not match" | Wrong or deleted key. | `exakit source reauth docs --password-file <new key.json>`. |
| "No rows in ORDERS" | The mapping's `source` glob matches no files. | Fix the glob, then remove the source and connect again. |

## Reference

**`--set` keys:** `bucket`, `region`, `mapping` (a path, `auto` or
`auto:<folder>/`), `access_key_id`. The secret key comes from
`--password-file` or the hidden prompt, never an argument.

**Mapping format:** EDML 2.1.0 (`$schema`
`https://schemas.exasol.com/edml-2.1.0.json`), one table per file:
`source` (key or glob in the bucket), `destinationTable`, and `mapping.fields`
for JSON. See [step 2](#2-the-mapping).

**After you connect:** `exakit source check docs`, `exakit source reauth docs`,
`exakit source remove docs`. A change to the mapping needs a new connect.
