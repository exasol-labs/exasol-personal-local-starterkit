# Amazon S3 files

JSON, JSON Lines, CSV or Parquet files in an S3 bucket, read as tables. An
EDML mapping file on your computer says which files become which table.

> **Easiest: let your AI agent do it.** The skill `exasol-vs-s3` knows this connector.
>
> **You still need, on your computer:** the AWS CLI (`aws configure`) or the
> AWS Console, as someone who may create an IAM user and its access key.
>
> **Prefer to do it by hand?** Follow the steps below.

## What `exakit connect` asks for

| Field | Required | Example |
|---|---|---|
| Name (alias) for this connection | yes | `docs` |
| S3 bucket name | yes | `my-bucket` |
| AWS region of the bucket | yes | `eu-central-1` |
| EDML mapping on this computer: a .json file, or a folder of them | yes | `./mapping` |
| Access key ID | no (if the credential file holds it) | `AKIA...` |
| Secret access key | yes | (hidden, or a file) |

## Where to find each value

### 1. Bucket and region

- **Console:** S3 → Buckets → the AWS Region column.
- **CLI:**
  ```bash
  aws s3api get-bucket-location --bucket my-bucket   # null means us-east-1, EU means eu-west-1
  aws s3 ls s3://my-bucket/orders/ --recursive | head
  ```

A bucket name with dots is refused (its HTTPS name does not match the S3
certificate).

### 2. The mapping

One `.json` file per table, or a folder of them (at most 50). `source` is the
key or glob inside the bucket:

```json
{"$schema": "https://schemas.exasol.com/edml-2.1.0.json",
 "source": "orders/*.jsonl", "destinationTable": "ORDERS",
 "mapping": {"fields": {"order_id": {"toDecimalMapping": {"decimalPrecision": 10, "decimalScale": 0}},
                        "status": {"toVarcharMapping": {"varcharColumnSize": 20}}}}}
```

CSV and Parquet may leave out `mapping` and have their columns inferred; JSON
needs its fields.

### 3. A read-only access key

The key needs `s3:ListBucket` on the prefix and `s3:GetObject` on its objects
(plus `kms:Decrypt` for a KMS-encrypted bucket).

- **Console:** IAM → Users → Create user (`exakit-docs-reader`, no console
  access) → Attach policies directly → Create policy → JSON (below). Then the
  user → Security credentials → Create access key → Third-party service →
  download the `.csv`.
- **CLI:**
  ```bash
  cat > exakit-s3-read.json <<'JSON'
  {"Version": "2012-10-17", "Statement": [
    {"Effect": "Allow", "Action": "s3:ListBucket", "Resource": "arn:aws:s3:::my-bucket",
     "Condition": {"StringLike": {"s3:prefix": ["orders/*"]}}},
    {"Effect": "Allow", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::my-bucket/orders/*"}]}
  JSON
  aws iam create-user --user-name exakit-docs-reader
  aws iam put-user-policy --user-name exakit-docs-reader --policy-name exakit-read \
    --policy-document file://exakit-s3-read.json
  umask 077; mkdir -p ~/.config/exakit
  aws iam create-access-key --user-name exakit-docs-reader > ~/.config/exakit/docs-key.json
  ```

The CLI's JSON holds both the key ID and the secret. From the console `.csv`,
put only the secret in a file and give the key ID with `--set access_key_id=`.
`aws sts` temporary credentials work too (the whole JSON, session token
included); they expire. The kit never reads `~/.aws`.

### 4. Network

Nothing to open by default. A bucket policy that limits `aws:SourceIp` must
include your public IP (`curl https://checkip.amazonaws.com`). A bucket
reachable only through a VPC endpoint cannot be read from your computer.

## Connect

```bash
exakit connect s3
```

The kit asks for a connection string (hidden; press Enter on an empty line to
type the fields instead), then each field above. It checks the mapping, shows
a plan with the mapped tables and asks once. The first connect installs Java
in the database (one restart). Your tables appear as `VS_DOCS.ORDERS`.

Without prompts:

```bash
exakit connect s3 --name docs --set bucket=my-bucket --set region=eu-central-1 \
  --set mapping=./mapping --password-file ~/.config/exakit/docs-key.json --yes
exakit sql "SELECT * FROM VS_DOCS.ORDERS LIMIT 10"
```

Add `--dry-run` to see the plan first.

**Windows:** paste the URL at the prompt rather than `--url`. For a quoted name
in `exakit sql`, pipe the statement in (`'SELECT "x" FROM VS_DOCS.T' | exakit sql`)
or use `exakit sql --file query.sql`.

## Connection string you can paste

```text
s3://my-bucket/orders/
https://my-bucket.s3.eu-central-1.amazonaws.com/orders/
```

The first fills the bucket; the second fills bucket and region. The path after
the bucket is not used: the mapping names the files.

## Common problems

| Symptom | Fix |
|---|---|
| "AccessDenied ... not authorized to perform: s3:ListBucket" | Grant the action on that prefix (step 3), then `exakit source check docs`. A bucket policy on `aws:SourceIp` answers the same: allow your IP. |
| "PermanentRedirect", "must be addressed using the specified endpoint" | Wrong region: `exakit source remove docs`, then connect with the bucket's region. |
| "RequestTimeTooSkewed" | The database clock is off by more than 15 minutes: `exakit stop`, then `exakit start`. |
| "InvalidAccessKeyId", "signature we calculated does not match" | Wrong or deleted key: `exakit source reauth docs --password-file <new key.json>`. |
| "No rows in ORDERS" | The mapping's `source` glob matches no files: fix the glob, then remove and connect again. |
